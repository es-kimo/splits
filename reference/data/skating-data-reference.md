# 대한체육회 빙상 경기결과 시스템 — 리버스 엔지니어링 (v2)

`result.sports.or.kr/SK/` 전체 구조.
v1 대비 **대회 중심 수집 경로가 확정**되어 전면 개정.

전부 실제 응답으로 검증됨. 추측은 별도 표기.

---

## 0. v1에서 바뀐 것

| 항목      | v1                              | v2                                      |
| --------- | ------------------------------- | --------------------------------------- |
| 수집 축   | 선수 중심 (`INF703` → `INF503`) | **대회 중심** (`INF201` → … → `INF310`) |
| 전수 열거 | 성씨 완전 탐색 (누락 위험)      | 대회 순회 (누락 없음)                   |
| 증분      | 불가                            | **가능** (신규 대회만)                  |
| 확보 필드 | 순위·기록                       | + BIB·레인·**학년**·실격사유·기록차     |

`INF503` 경로는 여전히 유효하며, 특정 선수의 전 커리어 조회에 쓴다.
두 소스의 값이 일치하는 것을 검증 완료(아래 7절).

## 1. 시스템의 성격

### `.do` 는 파일이 아니다

자바 웹 프레임워크(Struts / Spring MVC 계열)의 URL 매핑 관례.
`INF###` 은 화면 ID이며 번호 자체에 규칙적 의미는 없다.

### API가 아니다

문서화된 계약이 없고 HTML을 반환한다.
로그인이 필요 없다는 의미에서만 "공개"이며, 이를 긁는 것은 스크래핑이다.

**언제든 깨진다고 가정하고 설계할 것.** 응답은 반드시 로컬 캐싱.

### 공통 요청 규격

```
POST https://result.sports.or.kr/SK/INF###.do
Content-Type: application/x-www-form-urlencoded
```

- **쿠키 불필요.** 세션 없이 단발 POST로 동작
- UTF-8, User-Agent·Referer 불필요
- 빈 값은 빈 문자열로 전송
- 모든 화면이 `<form name="SearchVO">` 하나를 공유하며,
  JS 함수가 필요한 필드만 채워 submit 한다

### SearchVO 폼 필드 전체

```
classCd, toCd, pclassCd, eventCd, movSeq, teamCd, idNo,
kindCd, detailClassCd, baseClassCd, baseClassNm, rhCd, rhNm,
pcntGbn, useGbn, groupCd, gameCd, nslRound,
searchKindCd, searchDetailClassCd, searchKeyword, searchAppYn,
searchEntryGb, searchApprovalGb, searchEventNmGb, searchEventNm,
searchStartDt, searchEndDt, searchPlaceNm, searchGmDt, pageIndex
```

## 3. 파라미터 코드 체계

### `classCd` — 종목 (확정)

| 값  | 종목           | 근거                            |
| --- | -------------- | ------------------------------- |
| 1   | 스피드스케이팅 | 대회명 대조                     |
| 2   | 쇼트트랙       | 대회명 대조                     |
| 3   | 피겨스케이팅   | `fnEventStartList` 내 분기 코드 |

대회마다 유효한 `classCd` 가 다르다.
스피드 대회에 `classCd=2` 로 조회하면 세부종목 0건이 나온다(에러 아님).

### `toCd` — 대회 코드

자릿수가 고정되지 않는다. 예: `201202`(6자리), `207088`(6자리), `202600071`(9자리)

`toCd` 에서 연도를 파싱하지 말고, 대회명/일자에서 연도를 복원해야 한다.

### `kindCd` — 종별

| 값           | 종별                         |
| ------------ | ---------------------------- |
| 21 / 22      | 남자부 / 여자부 (오픈)       |
| 31 / 32 / 33 | 남자초등 1·2 / 3·4 / 5·6학년 |
| 41 / 42 / 43 | 여자초등 1·2 / 3·4 / 5·6학년 |

중·고·대학부 코드는 미확인. 앞자리가 학령대, 뒷자리가 성별·세부구분으로 보인다(추정).

### `detailClassCd` — 종별 × 거리

`2{kindCd}0{거리코드}` 패턴.

```
kindCd=22, 500M  → 22201
kindCd=33, 500M  → 23301
kindCd=31, 1000M → 23103
```

### `baseClassCd` — 거리만 ★ 혼동 주의

| 값  | 거리  |
| --- | ----- |
| 01  | 500M  |
| 03  | 1000M |
| 04  | 1500M |

**`detailClassCd` 와 다른 값이다.** 둘 다 숫자라 헷갈리기 쉽고,
틀리면 에러가 아니라 **조용히 0건**이 나와 알아채기 어렵다.

`fnEventResult` 의 3번째 인자 이름이 `detailClassCd` 이지만
실제로 넘어오는 값은 `"01"` 이고, 함수 내부에서
`frm.baseClassCd.value = detailClassCd` 로 세팅된다.
**인자 이름에 속지 말 것.**

### `rhCd` — 라운드 (확정)

| 값  | 라운드   |
| --- | -------- |
| 1   | 예선     |
| 4   | 준준결승 |
| 5   | 준결승   |
| 8   | 결승B    |
| 9   | 결승     |

**라운드를 고정 순회하지 말 것.** 세부종목마다 존재하는 라운드가 다르다.
반드시 `INF301` 에서 실제 목록을 얻어 그대로 따라간다.

### `pcntGbn` — 개인/단체

`I` = 개인, `T` = 단체가 관측된다. 대회에 따라 빈 문자열(`""`)도 존재한다.

빈 값을 임의로 `I`로 보정하면 오탐이 생기므로 원본값을 그대로 전달한다.

## 4. 화면별 상세

### INF201 — 대회 목록

```
POST pclassCd=SK&pageIndex=N
→ onclick="fnEventInfo('{classCd}','{toCd}')"
```

- 총 383건 / 39페이지 (10건/p). 이 중 쇼트트랙(`classCd=2`)은 132건.
- 같은 행에 대회명(`<td class="tal">`)과 개최장소

### INF202 — 표시용 대회 개요

```
POST classCd={1|2}&toCd={대회코드}&pageIndex=1
→ <tr onclick="javascript:fnEventSchedule('{kindCd}','{detailClassCd}')">
```

테이블 2개: `대회정보`, `세부종목 내역`

세부종목 행 컬럼:

```
종별 | 세부종목 | 경기방식 | 참가인원 | 참가팀
```

참가인원/코드 값이 실제 조회 파라미터와 자주 어긋난다.
수집 경로/검증 기준으로 사용하지 않는다.

실무 규칙: `INF202` 값은 화면 표시 참고용으로만 보고, 요청 파라미터는 `INF301` 드롭다운 + AJAX 응답으로만 확정한다.

### INF301 — 경기일정 (라운드 목록) ★

```
POST classCd=2&toCd={대회}&pageIndex=1
→ <select id="searchKindCd"> 옵션으로 kindCd 목록 획득

POST /SK/code/selectDetailClassCdListAjax.do
Content-Type: application/json; charset=UTF-8
{"classCd":"2","toCd":"{대회}","kindCd":"{종별}"}
→ DETAIL_CLASS_CD 목록 획득

POST classCd=2&toCd={대회}&kindCd={종별}&detailClassCd={종별×거리}
     &searchKindCd={종별}&searchDetailClassCd={종별×거리}&pageIndex=1
→ onclick="fnEventResult('','I','{baseClassCd}','{rhCd}','{rhNm}','{baseClassNm}')"
```

테이블: `대회정보`, `경기일정 내역`
컬럼: 종별 | 세부종목 | 경기일시 | 경기구분 | 경기장 | 경기결과

**실제로 존재하는 라운드만 나온다.** 이 단계를 건너뛰면 헛요청이 발생한다.

### INF310 — 경기결과 ★★ 실데이터

```
POST classCd=2&toCd={대회}&kindCd={종별}&detailClassCd={종별×거리}
     &baseClassCd={거리}&rhCd={라운드}&rhNm={라운드명}
     &baseClassNm={거리명}&pcntGbn=I&useGbn=
     &searchKindCd={종별}&searchDetailClassCd={종별×거리}&pageIndex=1
```

테이블: `기본정보`, `경기결과`

컬럼 14개:

```
대회명 | 대회기간 | 개최장소 | 경기구분 | 순위 | BIB | 성명 |
소속 | 학년 | 레인 | 기록 | 사유 | AD | 기록차
```

- 라운드 구분은 `<th scope="row" colspan="10">결승Final</th>` 형태
- 성명은 `<td class="tal"><a href="javascript:fnViewHistory('{idNo}');">이름</a></td>`
- 헬멧색이 별도 컬럼으로 들어감 (`노`, `빨`, `흰`, `파`)

**`INF503` 에 없는 필드:** BIB, 레인, 헬멧색, **학년**, 실격사유, AD, 기록차.
특히 학년은 나이 추정 정확도를 크게 올린다.

### INF302 / INF309 — 참가선수 명단 / 스타트리스트

**대개 비어 있다.** "참가선수명단이 없습니다" 반환.
사전 신청·배정 데이터로 보이며, 대회 종료 후에는 남지 않거나
애초에 입력되지 않는 것으로 추정.

컬럼 구조는 유용하나(성명·성별·**출생년도**·소속팀·학년·시도)
데이터가 없으므로 수집 경로로 쓸 수 없다.

### INF503 — 선수 대회참가이력

```
POST pclassCd=SK&idNo={선수ID}&pageIndex=1
```

- **페이지네이션 없음.** `pageIndex` 를 무시하고 전체 반환.
  실측: pageIndex 1/2/3 응답이 바이트 단위 동일(311,604 bytes)
- 최민정 기준 275행(19년치)이 단일 응답에 포함
- 테이블 2개: `최종등록정보`(4행), `대회참가이력`
- `최종등록정보` 에 **출생년도**와 소속팀 코드(`성남시청 (SK00445)`)

### INF703 — 선수 검색

- 10건/페이지, 범위 초과 시 빈 결과
- 페이지 간·페이지 내 중복이 정상적으로 존재 (ORDER BY 불안정 추정)
- 화면 표시 건수는 실제 행 수와도 고유 선수 수와도 불일치

### INF308 — 경기영상 목록

```
POST pclassCd=SK&pageIndex=N
→ onclick="fnVodDetail('SK','{eventCd}','{movSeq}')"
```

- 12건/페이지, 총 511페이지 / **6,129건**
- 상세는 GET이므로 그대로 링크 가능:
  `https://vod.sports.or.kr/vod/view.do?pclassCd=SK&eventCd={eventCd}&movSeq={movSeq}`
- 영상은 **유튜브가 아니라 Wowza 자체 스트리밍**
  `https://media.sports.or.kr/gamevod/_definst_/mp4:SK/{연도}/{eventCd}/{uuid}.mp4/playlist.m3u8`
- 썸네일: `https://vod.sports.or.kr/u/image/{YYYY}/{MM}/{DD}/{uuid}_thumb.JPG`
- VOD 상세의 "관련영상"에 다른 `movSeq` 는 노출되지 않음.
  `INF308` 목록이 유일한 수집 경로
- **VOD 메타데이터에 선수명이 포함된다** (개인정보 정책상 주의)

## 5. 파싱 함정

### 5-1. 타임스탬프 오염 ★★

```html
<script src="/comn/front/js/com.js?v=1785426145197" defer></script>
```

13자리 밀리초 타임스탬프. `[0-9]{12}` 로 긁으면 앞 12자리가
idNo처럼 잘려 나오고 **매 요청마다 값이 달라진다.**

→ HTML 전체에 정규식을 던지지 말 것.
구조로 좁힌 뒤(테이블 → 행 → onclick/href) 그 안에서만 패턴 적용.

### 5-2. 화면마다 idNo 위치와 함수명이 다르다 ★★

| 화면   | 함수                | 위치                         |
| ------ | ------------------- | ---------------------------- |
| INF701 | `fnPlayerHistory`   | `<button onclick>`           |
| INF703 | `fnPlayerHistory`   | `<tr onclick>`               |
| INF310 | **`fnViewHistory`** | **`<a href="javascript:">`** |

파서는 함수명을 고정하지 말고 `fn\w*History\(` 정도로 느슨하게,
`onclick` 과 `href` 를 **모두** 확인할 것.

```python
r'fn\w*History\(\s*["\']?(\d{6,})'
```

### 5-3. `<td>` 안이 항상 텍스트는 아니다

`INF310` 의 성명은 `<td class="tal"><a>이름</a></td>`.
`<td[^>]*>[^<]+</td>` 로 긁으면 **이름 컬럼만 통째로 사라진다.**
반드시 BeautifulSoup 등으로 파싱해 `get_text()` 를 쓸 것.

### 5-4. 테이블은 caption으로 선택

`INF310` 은 `기본정보` + `경기결과`,
`INF503` 은 `최종등록정보` + `대회참가이력`.
인덱스로 고르면 4행짜리 메타 테이블을 데이터로 착각한다.

### 5-5. 자릿수를 12로 고정하지 말 것

관측된 idNo 체계가 최소 3종. `\d{6,}` 로 받는다.

### 5-6. 빈 값이 정상적으로 존재

`fnPlayerHistory("")` 는 오류가 아니다. `idNo=None` 으로 보존.

### 5-7. 화면 표시 건수를 신뢰하지 말 것

"남윤창" 검색 기준: 표시 13 / 실제 행 23 / 고유 idNo 2. 셋 다 다르다.
종료 조건이나 검증 판정에 쓰지 말 것.

### 5-8. 페이지네이션 종료 조건

`INF703` 은 페이지 간·페이지 내 중복이 정상적으로 존재한다.
"새로운 행이 없으면 중단"은 오작동한다.
**"파싱된 행이 0개면 중단"** 하나만 쓴다. `max_pages` 안전장치 필수.

### 5-9. HTML 엔티티

onclick 안 따옴표가 `&#34;` 로 인코딩. BeautifulSoup을 거치면 정규화되므로
정규식은 따옴표를 옵셔널로 둔다.

### 5-10. `&&` 체인 주의 (진단 스크립트)

`grep` 은 매칭 0건에 종료코드 1을 반환한다.
진단 명령을 `&&` 로 이으면 거기서 끊긴다. `;` 를 쓸 것.

### 5-11. `diff` 로 응답 동일성 판정 시

타임스탬프 때문에 항상 "다름"이 나온다.

```bash
diff <(sed 's/[0-9]\{13\}//g' a.html) <(sed 's/[0-9]\{13\}//g' b.html)
```

## 6. 데이터 모델

### 6-1. idNo 체계 최소 3종

| 형식       | 예시                           | 해석                     |
| ---------- | ------------------------------ | ------------------------ |
| `YYYYMM`+6 | `200604009460`, `201105000916` | 최초 등록 연월. 주 체계  |
| `98####`+6 | `981618000141`                 | 구 체계 추정. 전부 1~2행 |
| `70####`+6 | `701318000131/142/150/155`     | **연번.** 일괄 등록 사고 |

접두사로 필터링하지 말 것. **행 수와 소속 일치로 판별**해야
다른 시기·종목의 유사 사고도 잡힌다.

### 6-2. 학교명 미정규화로 인한 고아 레코드 ★

```
201105000916  남윤창  달산초등학교  남자초등3,4학년  대구  (정상, 22행)
701318000150  남윤창  달산초        남자초등3,4학년  대구  (고아, 1행)
```

같은 학교인데 표기가 달라 별도 선수로 등록됐다.
이규호·신동민·이동현에게도 같은 사고가 있다.

### 6-3. 한 idNo가 전 커리어를 커버 ★

```
201105000916 = 대구신천초 → 달산초 → 경신중 → 칠성고 → 한국체대 → 경희사이버대
```

초등 저학년부터 대학까지 하나의 id로 이어진다.
현재 idNo로 유년기 기록 조회가 가능하다.

### 6-4. 검색 결과는 등록이력 단위

`INF703` 은 (선수 × 소속 × 종별) 단위로 행을 반환한다.
남윤창 한 명이 23행. 반드시 idNo로 묶을 것.

### 6-5. 동명이인 실재

박지원은 2026/27 국가대표 명단에만 둘(여자 전북도청 / 남자 서울시청).
**소속 + 성별** 두 축으로 판별해야 한다.

## 7. 도메인 규칙

### 7-1. 순위는 라운드 안에서의 등수다 ★★

최민정 2007 초등부 500M:

```
예선5조      52.55  2위
준준결승3조   51.12  2위
준결승2조    51.20  5위
채점종합     51.20  9위   ← 실제 성적
```

무차별 평균하면 4.5위, 실제는 9위.
**성적은 `채점종합` > `결승` 순으로 단 하나만 채택.**

### 7-2. 결승이 예선보다 느린 것은 정상 ★★

쇼트트랙은 레인 없는 착순 경기. 결승에서 전술적으로 천천히 타다 막판에 붙는다.

```
김길리 1500m 초등: 예선 143.040 → 결승 178.132 (결승 1위)
최민정 1500m 오픈: 예선 157.060 → 결승 192.951 (결승 1위)
```

"결승이 예선보다 느림"을 이상치로 잡으면 214건 중 대다수가 1위 기록인 오탐.

→ 기록(시간) 분석에는 **예선 기록만**
→ 순위 분석에는 채점종합/결승
→ **이 종목에서 기록으로 실력을 비교하는 것 자체가 부적절하다**

### 7-3. `1500M` 과 `1500M S.F` 는 별개 경기

슈퍼파이널. 같은 날 두 번 탄다.

```
20210509  1500M      결승Final  02:21.700  2위
20210509  1500M S.F  결승Final  02:23.077  1위
```

거리를 뭉개면 그룹핑 키가 겹쳐 중복이 남는다(실측 56건).

### 7-4. 일자가 `-` 인 행 ★

`채점종합` 라운드는 특정 일자가 없어 `-` 로 들어온다.
연도가 NaN이 되지만 학령구간은 종별에서 파생돼 살아남아
**같은 성적이 두 번 집계된다.**

전국동계체육대회 회차 → 연도 복원:

```
연도 = 회차 - 88 + 2007
제88회=2007 … 제94회=2013 … 제100회=2019 … 제107회=2026
(제89·102·106회는 미개최 또는 데이터 없음)
```

### 7-5. 유사 대회명 구분

```
제30회 전국남녀 쇼트트랙 스피드스케이팅대회
제30회 전국남녀 종별 종합 쇼트트랙 스피드스케이팅 선수권대회
```

회차만으로 묶지 말 것. 대회명 전체 문자열로 구분.

### 7-6. 기록 형식이 여러 가지

```
"00:43.121" → 43.121      "2:58.30" → 178.30 (0 패딩 없음)
"01:34.394" → 94.394      "51.12"   → 51.12  (분 없음)
"05:06.73"  → 306.73      ""        → None
```

정규식 하나로 처리하지 말고 콜론 개수로 분기.

### 7-7. 종별 값

```
{성별}초등1,2학년 / 초등3,4학년 / 초등5,6학년 / 초등부
{성별}중학부 / 고등부 / 대학부 / 일반부
{성별}부                              ← 연령 무관 오픈
```

`여자부`/`남자부` 는 오픈이므로 학령 분석에서 제외.

### 7-8. 나이 계산의 한계

출생 연도만 있고 생월일이 없다.
`나이 = 대회연도 - 출생년도` 는 만 나이보다 최대 1살 높고,
**동계 대회가 1~2월에 몰려 있어 체계적으로 +1 편향**이 있다.

`INF310` 의 **학년** 필드를 쓰면 학령 구간 판정이 정확해진다.

## 8. 데이터 커버리지

연도별 기록 건수 (국가대표 14명 기준):

```
2007:  20    2012: 154    2017: 351    2022: —
2008:  18    2013: 137    2018: 385
2009:  19    2014: 282    2019: 420
2010:  28    2015: 288    2020: 130  ← 코로나
2011:  34    2016: 355    2021: 408
```

**2012년에 5배로 뛴다.** 그 이전은 전산화가 부분적이고
전국동계체육대회 같은 큰 대회만 남아 있다.

→ 1990년대 중반 이전 출생 선수는 유년기 기록이 통째로 비어 있다.
노아름(1991년생)의 초등부 기록 0건은 "출전하지 않음"이 아니라
"기록이 없음"이다. **이 둘을 구분할 수 없다는 점을 명시해야 한다.**

신뢰도 판정:

```
초등 6학년 추정연도 = 출생년도 + 12
  >= 2014  → high      2012~13 → medium      < 2012 → low
```

## 9. 수집 전략

### 9-1. 두 소스 일치 검증 완료 ★

2026 국대 2차 선발전(`toCd=202614500`) 여자부 500M 결승:

|             | INF503       | INF310       |
| ----------- | ------------ | ------------ |
| idNo        | 200604009460 | 200604009460 |
| 기록        | 00:43.632    | 00:43.632    |
| 라운드 표기 | 결승Final    | 결승Final    |

**동일한 DB를 보고 있으며 표기도 같다.** 정규화 규칙 불필요.
두 소스를 합쳐도 안전하나, 중복 방지 키는 필요하다.

부수 확인: 이 경기에 이소연(`200409019950`)이 출전.
국가대표 8인 명단에 없는 선수이므로,
**대회 경로가 선수 명단보다 넓게 잡는다.**

### 9-2. 전수 수집 비용

```
INF201   39 요청            대회 목록
INF301   132 요청           kindCd 목록(대회당 1회)
AJAX     132 × (6~15)       detailClass 목록
INF301   세부종목당 1회      라운드 목록
INF310   실제 라운드만 호출
─────────────────────────────────────────
합계 약 12,000~15,000 요청 / 1초 간격 = 약 3.5~4시간
```

라운드를 1/4/5/8/9 로 고정 순회하면 헛요청이 크게 늘어난다.
반드시 `INF301` 을 거칠 것.

### 9-3. 증분 수집 비용 ★

```
INF201 1페이지 (1 요청) → 신규 대회 없으면 종료
신규 대회 1개당:
  INF301(kind)  1 요청
  AJAX(kind별)  6~15 요청
  INF301(detail) 6~15 요청
  INF310  ~40 요청
  ───────────────────────────
  약 55~70 요청 / 1분
```

**데이터가 대회 단위로 생성되므로 수집 단위와 일치한다.**
증분이 구조적으로 자연스럽고, 주간 갱신이 1분이면 끝난다.

### 9-4. 요청 예절

- 간격 1초 이상, 병렬 요청 금지
- 응답 HTML 캐싱 필수. 재수집 시 서버를 다시 때리지 않는다
- User-Agent에 연락 가능한 정보를 넣는 것을 고려 (차단 시 협의 여지)

### 9-5. 폐기된 접근

| 방법                            | 폐기 이유                               |
| ------------------------------- | --------------------------------------- |
| 성씨 완전 탐색                  | 누락 위험, 4,300 요청, 증분 불가        |
| `INF302` 참가선수 명단          | 데이터가 비어 있음                      |
| `INF309` 스타트리스트           | 데이터가 비어 있음                      |
| VOD 메타에서 선수명 추출        | 이름만 있고 idNo 없음, 영상 있는 경기만 |
| `pageUnit`/`recordCountPerPage` | 서버가 무시함                           |

## 11. 다른 종목 확장 시

`GATE.do` 기준 64개 종목. 경로 예: `/SW/`(수영), `/RL/`(롤러), `/AT/`(육상)

`getRoot.do` (JSON, POST) 로 종목별 시스템 현황 조회 가능:

```
NO1 참가신청 / NO2 대회운영 / NO3 정보제공 / NO4 정보연계
```

- **NO3(정보제공)은 축구 제외 63개가 O** → 필터로 쓸 수 없다
- **NO1·NO2가 O인 42개 종목**은 이 시스템에서 직접 운영되어
  라운드별 상세 기록이 있을 가능성이 높다
- **NO4만 O인 종목**(육상 AT, 양궁 AR, 사격 SH, 테니스 TE,
  태권도 TA, 펜싱 FE, 유도 JU)은 외부 연맹에서 결과만 연계받아
  데이터가 얕을 수 있다

우선 확인 대상: 수영(SW), 롤러(RL), 수중핀수영(UW), 조정(RO), 카누(CA), 역도(WE)

**5절 파싱 함정 대부분은 템플릿 레벨 문제로 보이므로 그대로 재발할 가능성이 높다.**
반면 7절 도메인 규칙(라운드 위계, 착순 전술, 슈퍼파이널)은
쇼트트랙 고유이며 종목마다 새로 파악해야 한다.
