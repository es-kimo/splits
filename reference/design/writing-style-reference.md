# 국가대표 유년기 페이지 문체 가이드

현재 페이지 생성 기준: [build_site.py](../../build_site.py)

이 문서는 서비스 문구를 쓸 때 톤을 일관되게 유지하기 위한 참고 규칙이다.
강제 규칙이 아니라 기본 정책이며, 문맥상 더 자연스러운 표현이 있으면 우선한다.

## 1) 기본 원칙

- 사용자 안내/설명 문구는 `~요` 체를 기본으로 한다.
- 데이터 사실/방법론/한계 설명은 `~습니다` 체를 기본으로 한다.
- 하나의 단락에서 종결 어미를 자주 섞지 않는다.
- 과장/단정 대신, 관측 가능한 사실 중심으로 쓴다.

## 2) 문장 톤 분리

### A. 서비스 제공자 안내 톤 (`~요`)

주로 다음 영역에 사용한다.

- 도입부 소개
- 보는 방법 안내
- 인터랙션 안내
- 부담을 낮추는 주의 문구

예시 성격

- "정리했어요"
- "볼 수 있어요"
- "믿기는 어려워요"

### B. 분석 결과/팩트 톤 (`~습니다`)

주로 다음 영역에 사용한다.

- 계산 근거
- 기준/정의
- 데이터 누락 및 한계
- 오해 방지를 위한 설명

예시 성격

- "채점종합 기준입니다"
- "전산화돼 있습니다"
- "원본 그대로 두었습니다"

## 3) 섹션별 권장 톤

- 헤더/인트로: `~요` 우선
- "이렇게 보세요" 박스: `~요`
- 요약 3문장: 내용 성격에 따라 혼합 가능, 같은 문장 안에서는 한 톤 유지
- 데이터 한계/방법론: `~습니다` 우선
- 푸터 출처/면책: 중립 서술형 (`~입니다` 또는 명사형)

## 4) 어휘 선택 원칙

- 쉬운 단어를 우선 사용한다.
- 전문 용어를 쓰면 바로 뒤에 짧게 풀어쓴다.
- 동일 개념은 동일 어휘를 유지한다.
  - 예: "기록이 없다" 대신 "기록이 남아 있지 않다"로 통일

## 5) 금지/주의 패턴

- 근거 없는 확정형 표현
  - 예: "반드시", "완전히", "절대"
- 독자가 오해할 수 있는 인과 단정
  - 예: "어릴 때 1등이면 국가대표가 된다"
- 데이터 결측을 실력 결론으로 연결하는 표현

## 6) 빠른 체크리스트

- 이 문장은 안내인가, 사실 설명인가?
- 안내 문장이라면 `~요`가 자연스러운가?
- 사실 문장이라면 `~습니다`가 자연스러운가?
- 같은 문단 안에서 어미가 튀지 않는가?
- 과장/단정 없이 근거가 보이는가?

## 7) 업데이트 규칙

- 실제 페이지 문구가 크게 바뀌면 이 문서도 함께 갱신한다.
- 문체 기준 충돌 시, 최신 `build_site.py` 출력 문구를 우선한다.
