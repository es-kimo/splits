# 개인정보 열람·정정·삭제·처리정지 요청 내부 절차

본 문서는 `https://es-kimo.github.io/splits/` 운영자가 개인정보 관련 요청을 처리할 때 따르는 내부 기준입니다.
법률 자문 문서가 아니며, 서비스 범위 변경 시 함께 갱신합니다.

## 1. 접수 채널

- 접수 채널: 개인정보 처리방침 페이지에 공개한 전용 이메일
- 접수 범위: 열람, 정정, 삭제, 처리정지
- 접수 즉시 해야 할 일
  1. 접수 시각(한국시간) 기록
  2. 요청 유형 분류
  3. 대상 선수 식별자 기록(선수명, `idNo`, 페이지 URL 중 확인 가능한 값)

## 2. 본인/법정대리인 확인

- 본인 요청
  - 공개 페이지 정보와 요청 메일 내용이 합리적으로 일치하는지 확인
  - 필요 시 추가 확인 질문 1회 발송(예: 대상 페이지 URL 재확인)
- 법정대리인 요청
  - 대리 요청 사유 확인
  - 보호자/대리 권한 확인 가능한 최소 증빙 요청

확인이 불충분하면 보완 요청을 보내고, 보완 전까지 처리 상태를 `확인대기`로 둡니다.

## 3. 처리 원칙

- 확인이 완료된 요청은 지체 없이 처리합니다.
- 처리 결과(완료/부분완료/반려)와 사유를 반드시 회신합니다.
- 반려 시에는 부족한 정보와 재요청 방법을 함께 안내합니다.

## 4. 삭제 요청 처리 범위

삭제 요청이 승인되면 아래 범위를 순서대로 처리합니다.

1. 페이지 삭제
   - `athlete/{idNo}/index.html` 또는 요청 대상 페이지 콘텐츠 제거
2. 데이터셋 제거
   - 빌드 원본에서 해당 선수 데이터 제외 후 `python build_site.py` 재생성
3. 색인 삭제 요청
   - Google Search Console 및 네이버 서치어드바이저에서 대상 URL 삭제 요청

## 5. 검색엔진 색인 삭제 절차

### Google Search Console

1. 속성 `https://es-kimo.github.io/splits/` 선택
2. `색인` 또는 `삭제` 메뉴 진입
3. 대상 URL 입력 후 임시 삭제 요청 제출
4. 제출 시각 및 요청 ID(표시되는 경우) 기록

### 네이버 서치어드바이저

1. 사이트 `https://es-kimo.github.io/splits/` 선택
2. 웹마스터 도구에서 URL 삭제/수집 제외 메뉴 진입
3. 대상 URL 등록 후 요청 제출
4. 제출 시각 및 처리 상태 기록

## 6. 처리 이력 기록

요청 건마다 아래 항목을 남깁니다.

- 요청 번호(날짜+순번)
- 접수 시각
- 요청자 유형(본인/법정대리인)
- 요청 유형(열람/정정/삭제/처리정지)
- 대상 식별자(선수명, `idNo`, URL)
- 확인 완료 시각
- 조치 내용(페이지/데이터셋/색인)
- 회신 시각 및 결과
- 비고(보완 요청, 반려 사유 등)

## 7. 운영 메모

- 공지된 이메일/책임자 정보가 바뀌면 `/privacy/` 페이지와 본 문서를 같은 배포에서 함께 갱신합니다.
- 반복 요청이 누적되면 별도 티켓 체계로 전환해 추적성을 강화합니다.
