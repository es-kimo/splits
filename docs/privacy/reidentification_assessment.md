# 개인 기록 매칭 재식별 위험 평가

- 평가일: 2026-09-07
- 결정: 수용 불가 — 개인 기록 매칭을 제공하지 않음
- 범위: 공개 경기 결과를 입력받아 익명화된 선수 기록 또는 개인 레이팅 조회 권한을 찾는 모든 서버·클라이언트 기능

## 결론

공개 경기 결과를 아는 사람은 서로 다른 세 대회의 기록 또는 순위를 조합해 익명 레코드를 매우 높은 확률로 한 명으로 좁힐 수 있습니다. 특히 기록을 사용한 경우 평가 대상 전원이 단일 후보가 되었습니다. 대상에 미성년자가 포함되고, 공개 엔드포인트에서 이 공격을 구별할 방법이 없으므로 잔여 위험은 수용하지 않습니다.

이 서비스는 개인 기록 매칭, 매칭용 세션 토큰, 브라우저 내 매칭을 제공하지 않습니다.

## 위협 모델

공격자는 공개된 경기 결과를 열람할 수 있고, 특정 아동이 참가한 대회·거리와 기록 또는 순위 세 건을 알고 있다고 가정합니다. 이는 보호자, 코치, 동료 선수, 지역 커뮤니티 구성원처럼 해당 아동의 경기 이력을 이미 아는 사람에게 현실적인 사전 지식입니다.

공격의 목적은 익명 레코드와 실제 인물을 연결한 뒤, 개인별 레이팅 또는 그 밖의 비공개 조회 결과를 얻는 것입니다. 공격자는 로그인하지 않으며, 서비스가 “학부모만 사용할 것”이라고 가정하지 않습니다.

## 측정

2026-09-07에 공개 익명 경기 데이터 128,912행을 사용해 측정했습니다. 선수별로 서로 다른 대회의 유효 결과 세 건을 선택하고, 각 결과에서 대회와 거리를 고정한 뒤 기록 또는 순위를 차례로 교차했습니다. 결측 기록·순위는 해당 입력 종류의 측정에서 제외했습니다. 같은 대회 안의 여러 라운드는 증거 수를 부풀리지 않도록 한 건만 사용했습니다.

| 입력 근거 | 세 대회 입력이 가능한 선수 | 단일 후보 | 비율 |
| --- | ---: | ---: | ---: |
| 대회·거리·기록 | 1,420명 | 1,420명 | 100.00% |
| 대회·거리·순위 | 1,443명 | 1,030명 | 71.38% |

이 평가는 대표적인 세 입력 조합 하나씩을 사용한 하한 측정입니다. 기록의 정밀도, 드문 종목, 추가 대회 정보는 공격자에게 더 유리할 수 있습니다. 개인을 식별할 수 있는 입력 조합, 익명키, 후보 목록은 기록하지 않았습니다.

## 공격 비용과 통제 한계

목표 아동의 세 결과를 아는 표적 공격은 완성된 입력을 한 번 제출하면 됩니다. 후보 수를 중간에 표시하지 않아도 공격자는 후보 수를 알아야 할 필요가 없으며, 성공 시 발급되는 토큰 자체가 식별 신호가 됩니다.

| 검토한 통제 | 높이는 비용 | 충분하지 않은 이유 |
| --- | --- | --- |
| 서로 다른 세 대회 증거 | 모르는 대상을 무작위 탐색하는 비용 | 표적 공격자는 공개 결과 세 건을 이미 알고 있어 요청 1회로 충족합니다. |
| 중간 단계 k=10 하한과 동일 실패 응답 | 후보 수를 이용한 점진 탐색 비용 | 완성된 세 입력의 성공 여부가 단일 후보 정보를 다시 제공합니다. |
| 구간 응답 | 정밀 레이팅 값의 추가 노출 | 매칭 성공 자체가 개인과 익명 레코드의 연결입니다. |
| IP·토큰 제한 | 대량 열거 비용 | 단일 표적 공격에는 영향이 작고, IP 우회도 가능합니다. |
| 24시간 토큰 | 영구 링크의 보존 비용 | 공격자는 유효 기간 안에 한 번 조회하면 됩니다. |
| 입력·매칭 해시 연결 로그 금지 | 운영 로그의 추가 노출 | 외부 공격자가 매칭 결과를 얻는 문제를 막지 못합니다. |
| 응답 시간 평준화 | 타이밍 부채널 | 성공/실패의 기능적 차이가 남아 있습니다. |

## 대안 비교

서버 매칭은 서버가 익명 레코드를 찾아 토큰을 발급하므로 표적 공격에 직접적인 조회 경로를 만듭니다. 브라우저 매칭은 서버가 누가 누구인지 알지 못하게 할 수 있지만, 전체 익명 코호트 또는 동등한 매칭 인덱스를 이용자에게 배포해야 합니다. 이는 더 넓은 재식별 시도와 로컬 복제를 가능하게 하므로 위험을 낮추지 않습니다.

두 방식 모두 채택하지 않습니다.

## 삭제·처리정지 요청

현재 개인 기록 매칭 서비스, 매칭 세션, 매칭 토큰, 매칭 전용 저장소가 없으므로 승인된 삭제·처리정지 요청을 매칭 경로에서 따로 제거할 대상도 없습니다. 기존 공개 페이지와 공개 대상 명단의 제거 절차는 계속 적용합니다.

향후 재검토가 승인되더라도, 승인된 요청 대상은 어떤 후보 계산보다 먼저 적용되는 운영 차단 목록에서 즉시 제외되어야 합니다. 이 목록의 갱신과 배포 완료가 확인되기 전에는 매칭 기능을 재가동할 수 없습니다.

## 재검토 조건

재도입하려면 새로운 설계가 표적 공격의 실질적 비용을 올린다는 독립 평가, 삭제 제외의 즉시성 검증, 개인정보 영향에 대한 사람의 검토와 명시적 승인까지 모두 충족해야 합니다. 단순한 IP 제한, 단기 토큰, 후보 수 숨김만으로는 재검토 조건을 충족하지 못합니다.
