# ADR 0015 — 정적 제공과 질의 API 경계 (R-13)

- 상태: Accepted
- 작성일: 2026-09-07
- 선행: `docs/adr/0011-run-registry.md`, `docs/adr/0012-filter-vs-smoother.md`

## 문맥

아카이브, 코호트 분포, 공인 선수의 궤적은 배치 시점에 모두 계산할 수 있습니다.
이 데이터를 동적으로 제공하면 질의 공간을 줄이거나 사용자 입력을 반영하지 못한 채
가용성 의존성만 추가합니다.

R-14 시뮬레이션과 R-15 개인 매칭은 재현 가능한 완료 레이팅 실행을 고정해 조회하는
최소 질의 경로가 필요합니다. 서버는 레이팅 상태를 소유하거나 바꿔서는 안 됩니다.

## 결정

1. 코호트 요약과 공인 선수의 회고 궤적은 `site/build_static.py`가 정적 자산으로
   생성합니다. 표본이 10명 미만인 코호트 자산은 생성하지 않습니다.
2. 공인 선수 정적 궤적에는 스무딩 스냅샷을 사용합니다. 동적 API 레이팅 조회는
   필터 스냅샷만 제공하며 `smoothed` 모드는 허용하지 않습니다.
3. API는 프로세스 시작 시 `runs/current`를 한 번 고정하고 완료 상태의 실행만
   사용합니다. 레지스트리 SQLite는 URI `mode=ro`로 열며, `current` 변경은 명시적
   프로세스 재시작 후에만 응답에 반영됩니다.
4. 배치는 비공개 SQLite 매핑에 안정적인 무작위 불투명 ID를 발급합니다. 이 매핑은
   Git과 배포 정적 자산에서 제외하며, 공개 상태 선수만 내부 선수 식별자와 연결합니다.
5. 모든 레이팅 응답에는 실행 출처, 보정기 식별자, 데이터 기준일, 경과 일수를
   포함합니다. `n_games <= 5`이면 `confidence: low`를 반환하고 레이팅 숫자 대신
   판단 유보 문구를 제공합니다. R-05의 측정 구간에 따라 6회 이상은 `high`로
   판단하며, `medium`은 측정 근거가 생길 때까지 사용하지 않습니다.

## 결과

- 아카이브, 분포, 공인 선수 궤적은 API 장애 중에도 정적 자산만으로 동작합니다.
  이후 시뮬레이션과 개인 추정 화면만 비활성화하면 됩니다.
- 비공개 매핑의 백업과 교체는 배포 운영 책임입니다. 기존 매핑을 보존하지 않고
  ID를 다시 발급하면 이전 정적 자산 URL이 끊깁니다.
- 연령 보정 산출물에는 원본 `run_id`를 함께 기록합니다. API는 고정한 실행과 다른
  산출물을 거부해 서로 다른 실행의 상대값이 섞이는 것을 막습니다.

## 사용

먼저 `SPLITS_ANON_SALT`를 배치 프로세스에서 사용할 수 있게 설정한 뒤 완료된 레이팅
실행과 정적 자산을 생성합니다.

```bash
make rating
```

기본 비공개 매핑과 레지스트리 경로로 로컬 API를 실행합니다.

```bash
make api
```

연령 상대값을 함께 제공하려면 동일한 공개 실행에서 생성한 산출물 경로를
`SPLITS_AGE_ADJUSTED_PATH`로 설정합니다. 기본 경로와 다를 때만
`SPLITS_RATING_REGISTRY_ROOT`, `SPLITS_OPAQUE_ID_DB`를 설정합니다.
