# ADR 0015 — Static delivery and query API boundary (R-13)

- Status: Accepted
- Date: 2026-09-07
- Depends on: `docs/adr/0011-run-registry.md`, `docs/adr/0012-filter-vs-smoother.md`

## Context

The archive, cohort distributions, and public-athlete trajectories are fully
derivable during a batch build. Serving them dynamically would introduce an
availability dependency without reducing query-space or incorporating user input.

R-14 simulation and R-15 private matching need a small query surface that can pin
a reproducible completed rating run. That server must never own or mutate rating
state.

## Decision

1. Cohort summaries and public-athlete retrospective trajectories are generated by
   `site/build_static.py` into static assets. Cohort assets omit every group with
   fewer than 10 athletes.
2. Static athlete trajectories use smoothed snapshots. Dynamic API queries expose
   filtered snapshots only; `smoothed` is not an accepted API mode.
3. The API pins `runs/current` at process startup, accepts only a completed run,
   and opens the registry SQLite database with URI `mode=ro`. Changing `current`
   requires an explicit process reload to affect responses.
4. The batch issues stable random opaque IDs in a private SQLite mapping. The
   mapping is excluded from Git and deployable static assets. It maps only active
   public athletes and is the sole bridge from an external path to the internal
   athlete identifier.
5. Every rating response includes run provenance, calibration identifier, data
   cutoff date, and stale-day count. `n_games <= 5` returns `confidence: low`,
   suppresses rating numbers, and carries the display-defer message. The measured
   R-05 segments support `high` for six or more games; `medium` is reserved until
   a measured policy supports it.

## Consequences

- Archive, distribution, and public trajectory pages require no API request and
  continue to work during an API outage. Only future simulation and private
  estimation surfaces need to be disabled.
- Private mapping backup and rotation are deployment responsibilities. Reissuing
  IDs without preserving the mapping would break existing static asset URLs.
- The age-adjusted artifact carries its source `run_id`; the API rejects it when
  it does not match the pinned run, preventing mixed-run relative values.

## Usage

First generate a completed rating run and static artifacts, with
`SPLITS_ANON_SALT` available to the batch process:

```bash
make rating
```

Run the read-only API locally with the default private mapping and registry paths:

```bash
make api
```

Set `SPLITS_AGE_ADJUSTED_PATH` only when it points to the age-adjusted artifact
for the same published run. Set `SPLITS_RATING_REGISTRY_ROOT` and
`SPLITS_OPAQUE_ID_DB` when those private paths differ from their defaults.
